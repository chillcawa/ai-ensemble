# Security Policy

## Supported versions

Security fixes are made on the latest released version. This project is currently alpha software; older versions may not receive patches.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's **Security → Report a vulnerability** form (GitHub Private Vulnerability Reporting).

Include the affected version, platform, reproduction steps, and expected impact. Remove API keys, conversation content, database files, user paths, and other private data before attaching logs or screenshots. Maintainers will acknowledge a complete report when project availability permits; no response-time SLA is offered.

If private reporting is not enabled on a fork, contact that fork's maintainer through a private channel. Never post an active credential as a demonstration.
