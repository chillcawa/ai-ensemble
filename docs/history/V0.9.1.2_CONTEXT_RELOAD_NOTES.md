# AI Ensemble v0.9.1.2 — Context Reload Boundary

## 目的
Contextを調整したあと、現在のInstruction / Reference / Context Set / Session Contextを再評価し、
旧Context下で生成された会話履歴との境界を明示できるようにする。

## UI
ヘッダーの `🧩 Context` 横に `↻ 再読込` を追加。
まだConversationが存在しない場合は、旧履歴がないため無効。

## 再読込モード
### 履歴を保持して再読込
- 現在のContextを次回送信時に再Assembler
- 過去のConversation historyは従来どおりAIへ送る
- Conversation HistoryにはContext再読込境界を記録

### 以前の履歴を参照せず再読込
- 現在のContextを次回送信時に再Assembler
- Conversation自体・過去ログは削除しない
- `context_reload_reset` markerより前の通常メッセージを、以後のprovider historyから除外
- UIでは全Transcriptを引き続き閲覧可能

## 永続化
既存 `conversation_messages.kind` を利用。
新しいkind:
- `context_reload_keep`
- `context_reload_reset`

DB schema変更は不要。
markerには再読込時点の `applied_context_ids` をsnapshotとして保存する。

## 設計上の意味
これは「会話削除」ではなくContext Boundary。
履歴を保存しつつ、AIへ渡すhistoryだけを境界以降に限定できる。
Contextそのものは毎送信時に現在状態からAssemblerされるため、Context stateの複製は行わない。
