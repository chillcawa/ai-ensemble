# v0.9.2 hotfix3 — SQLite Hydration Guard

## 原因
v0.9でPersistent Context / Context Set / Set selectionをSQLiteへ移行した後も、
App.tsxの初期React stateだけは古いlocalStorage loaderを直接seedに使っていた。

そのため:
1. 起動直後に旧localStorage snapshotがruntime stateへ入る
2. SQLite hydrationが遅延/失敗すると旧Contextが見える
3. hydration失敗時にも `contextStorageReady=true` にしていたため、
   save effectが旧stateをSQLiteへ逆流させる危険があった

## 修正
- contextItems初期値 = []
- contextSets初期値 = []
- contextSetSelections初期値 = {}
- legacy localStorageを読む場所は「未移行時のone-time migration」のみに一本化
- SQLite hydration成功時だけ `contextStorageReady=true`
- hydration失敗時はreadyにせず、error stateを保持
- readyになるまで:
  - Context UIを開かない
  - Context Reload不可
  - AI送信不可
  - Context Libraryを開かない
