# v1.3.4 OSS release gate

The Windows publication gate is available as `RUN_OSS_RELEASE_CHECK.bat`.

It performs these operations in order:

1. Verifies Node.js, npm, Cargo, and rustup are available.
2. Installs rustfmt and Clippy components.
3. Installs locked npm dependencies and runs frontend verification.
4. Blocks high/critical production advisories, reports the full development tree, and blocks any
   critical advisory.
5. Generates `src-tauri/Cargo.lock` when it is not present.
6. Applies rustfmt, verifies formatting, and runs tests and Clippy with locked dependencies.
7. Builds the Windows NSIS installer and scans the executable.
8. Creates `AI-Ensemble-v1.3.4-OSS-VERIFIED-SOURCE.zip` for the final publication audit.

On Windows, Cargo output is written to a short directory below `%LOCALAPPDATA%` and the build uses
one parallel job. This avoids synchronized Desktop paths, excessive nesting, and parallel linker
contention without requiring an antivirus exclusion. Reruns reuse the latest v1.3.4 build cache.

The initial Windows run generated the dependency lockfile, passed six Rust tests, and reached
Clippy. The follow-up patch removes unused pricing code, uses the efficient reverse iterator,
accepts intentional high-arity Tauri/database boundaries locally, and applies the suggested
standard-library cleanup in application setup.

The generated Cargo lockfile must be committed. CI rejects source trees that omit it.
After the automated gate passes, install the generated package and confirm that the application
launches before creating a public release tag.
