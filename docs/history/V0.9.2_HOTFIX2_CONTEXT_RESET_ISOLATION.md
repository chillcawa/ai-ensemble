# v0.9.2 hotfix2 — Context Reset Isolation

## 症状
Contextを空にして `以前の履歴を参照せず再読込` しても、旧Instruction / Referenceの影響が残るように見えるケースがあった。

## 主因
`contextItemsForConversation()` の旧仕様で、Context Set未選択 (`null`) が
「blank」ではなく「全てのenabled Project/slot persistent Contextを有効化するlegacy/manual mode」
として扱われていた。

そのためSetを外したり削除した状態が、見た目上は空でも、裏では過去のPersistent Contextを再適用し得た。

## 修正
1. Context Set未選択 = blank
   - Global InstructionとConversation Session Contextは従来どおりSet外。
   - Project/slot persistent Instruction/Referenceは、Set未選択時には全て無効。
   - 過去Contextを暗黙に全復活させるfallbackを廃止。

2. Context Reloadを強化
   - Reload boundary作成前にContext Items / Sets / Set selectionsをSQLiteへ明示flush。
   - boundary保存後にConversation MessagesをSQLiteから再読込。
   - React stateの更新タイミングに依存しない。

3. Sendを強化
   - Providerへ送る直前にConversation MessagesをSQLiteから再読込。
   - `context_reload_reset` boundaryを必ず永続側から認識。
   - reload直後に素早く送信しても旧履歴を再送しない。

## 意味
`以前の履歴を参照せず再読込` は:
- boundary以前のConversation historyを送らない
- その時点で現在有効なContextだけを再Assemblerする
- Set未選択ならProject/slot persistent Contextはゼロ

※ Global Instruction / Session ContextはSet外という既存原則のため、
それらが有効ならblank Setでも適用される。完全にゼロへしたい場合はそれらも空/無効にする。
