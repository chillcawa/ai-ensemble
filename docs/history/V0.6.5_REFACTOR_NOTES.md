# AI Ensemble v0.6.5 — UI polish + Context-ready refactor

## v0.6.3 items closed

- Replaced native `window.confirm()` usage in TextPad/API key/Usage destructive actions with an app-internal centered modal.
- TextPad delete confirmation now appears at the center of the current app window.
- Added per-item deletion to paste history with centered confirmation.
- Added pin/unpin to paste history.
- Pinned history is excluded from the 30-item automatic cleanup limit; the newest 30 unpinned items are kept.
- Dark/light theme continues to cover the entire Tauri window.

## v0.6.5 internal refactor

- Split the former monolithic `App.tsx` into focused components:
  - `SettingsPanel`
  - `ProviderGrid`
  - `QuestionComposer`
  - `ResultBoard`
  - `TextPad`
  - `UsageDashboard`
  - `ConfirmModal`
- Moved app-level types, formatting, storage, slot defaults, and recommendation logic into dedicated modules.
- Slot identity is now independent from provider/model in result routing.
  - Broadcast targets/results carry `slotId`.
  - Results are keyed by `slotId`, allowing future duplicate-provider and duplicate-model slots.
- Nickname/model local settings are stored per slot, with migration fallback to the old provider-based keys.

## Context architecture v0.1 (internal only)

Added `src/context/` with:

- `types.ts` — ContextItem and normalized request contracts
- `assembler.ts` — target filtering, instruction ordering, reference separation
- `budget.ts` — non-destructive token estimate / context-limit warning foundation
- `README.md` — invariants and v0.7 target behavior

### Context invariants

1. Instruction != Reference
2. Import != Context
3. Add to Context != Persist
4. Persist Context != Send immediately
5. AI Response != System Prompt
6. AI -> AI is a human-approved single hop
7. Context overflow never triggers automatic deletion or summarization

No Context UI is exposed in v0.6.5. The goal is to make v0.7 implementable without pulling Context logic back into `App.tsx`.
