# v0.9 hotfix2 — one-time Context migration guard

Claude review found a resurrection bug in the pre-v0.9 localStorage -> SQLite migration.

## Problem
The old code treated an empty SQLite array/object as "not migrated yet". After a user deleted every Persistent Context/Set/selection, a restart could import stale localStorage again.

## Fix
- Added explicit SQLite migration flag: `migration_completed_v0_9`.
- Added state-key existence checks for:
  - `context_items_v1`
  - `context_sets_v1`
  - `context_set_selections_v1`
- Existing SQLite keys win even when their value is `[]` or `{}`. This protects users who already ran v0.9 and intentionally deleted all data before installing this hotfix.
- Legacy localStorage is imported only for state keys that have never existed.
- Migration completion is written only after all required migration writes succeed.
- Legacy localStorage is intentionally left untouched for rollback compatibility.
- Removed stray zero-byte `src-tauri/pricing.json.tmp`.

This hotfix includes hotfix1's Rust `list_projects()` lifetime fix.
