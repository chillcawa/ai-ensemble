# AI Ensemble v0.7.7 — Context Edit Safety

## Changes
- Context Instruction editors now use local drafts instead of immediately mutating saved Context on every keystroke.
- `編集をキャンセル` restores the last confirmed value.
- `更新` opens a centered in-app confirmation dialog; Context changes only after confirmation.
- While a field has unsaved edits, Ctrl+Z keeps the browser/native textarea undo behavior.
- After a confirmed update, Ctrl+Z on the clean editor offers a one-level rollback to the value from immediately before that update.
- Switching Context Set / AI editor resets the draft to that editor's confirmed value.
- Unsaved state is visible as `未保存の変更`.

## Design intent
Editing a Context Instruction is now a draft/confirm operation. Merely typing no longer changes the active Context sent to AI.

## SQLite safety follow-up
- Enabled `PRAGMA foreign_keys = ON` for every SQLite connection.
- This makes the existing `ON DELETE CASCADE` declaration effective instead of relying only on the current manual delete order.

## Deferred
- Persistent Context is still stored in localStorage. This is acceptable for the current instruction/reference data, but Memory/User Profile should not silently inherit this storage choice; storage sensitivity will be reviewed before that feature is implemented.
