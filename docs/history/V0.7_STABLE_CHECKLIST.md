# AI Ensemble v0.7 Stable Verification Checklist

Date: 2026-08-14
Target: v0.7.1 Context UX

## Pass criteria
v0.7 may be called stable only when all Critical tests pass on the Windows/Tauri build. High tests may have documented minor UI issues, but no data loss, wrong-context routing, uncontrolled AI-to-AI chaining, or usage/cost recording failure is allowed.

## A. Build / startup — Critical
- [ ] `npm install` completes without dependency failure.
- [ ] `npm run typecheck` completes with zero TypeScript errors.
- [ ] `npm run build` completes successfully.
- [ ] `npm run tauri:dev` compiles Rust and opens the desktop app.
- [ ] App can be closed and reopened without startup error.
- [ ] Dark mode fills the entire Tauri window when resized vertically and horizontally.

## B. API key / model — Critical
- [ ] OpenAI key can be saved from Settings and is reported as saved after restart.
- [ ] Anthropic key can be saved from Settings and is reported as saved after restart.
- [ ] Keys can be deleted only by explicit user action.
- [ ] Model discovery succeeds for each saved provider key.
- [ ] Choosing another compatible model persists after restart.
- [ ] A model unsupported by the current adapter cannot silently replace a compatible model and cause an unexplained 404/400.

## C. Normal send / streaming — Critical
- [ ] ChatGPT-only send works when only its checkbox is enabled.
- [ ] Claude-only send works when only its checkbox is enabled.
- [ ] Multi-AI send works when both are enabled.
- [ ] Streaming text appears incrementally without corrupting the final response.
- [ ] One provider error does not cancel the other provider's result.
- [ ] Completed responses show input/output tokens when the API supplies them.
- [ ] Completed responses show estimated cost or clearly say pricing is unavailable.

## D. Usage / SQLite — Critical
- [ ] One normal OpenAI request creates one usage record.
- [ ] One normal Anthropic request creates one usage record.
- [ ] One Handoff target request creates its own usage record.
- [ ] Today's total updates after a request.
- [ ] Provider totals update correctly.
- [ ] Usage remains after app restart.
- [ ] Clearing usage requires explicit user action and actually removes persisted usage.

## E. Context Instruction — Critical
- [ ] Global Instruction affects every selected AI.
- [ ] Project Instruction affects every selected AI in the current workspace.
- [ ] AI-specific Instruction affects only its matching slot.
- [ ] Global + Project + AI-specific are combined in the expected order.
- [ ] Emptying an Instruction field removes that Instruction from future sends.
- [ ] The composer visibly shows that active Context exists before send.

## F. Context Reference — Critical
- [ ] TextPad text can be added as a session Reference.
- [ ] A normal AI response can be added as an AI-generated Reference.
- [ ] Turning a Reference OFF excludes it from the next request.
- [ ] Turning it ON includes it again.
- [ ] Session Reference disappears after restart.
- [ ] Persistent Reference survives restart.
- [ ] Saving a Reference does not trigger an AI request.
- [ ] Adding a Reference does not automatically make it persistent.
- [ ] Deleting a Context item shows an in-app centered confirmation dialog.
- [ ] Deleting a persistent Context item removes it from persistence.

## G. Context safety invariants — Critical
- [ ] Reference text is not promoted to System/Instruction.
- [ ] AI-generated Reference is visibly distinguishable from user-authored Reference.
- [ ] Imported-conversation provenance exists in the type model but does not become active Context automatically.
- [ ] Context overflow warning never silently deletes an item.
- [ ] Context overflow warning never silently summarizes an item.

## H. One-hop Handoff — Critical
- [ ] From ChatGPT response, `他AIへ渡す` opens the handoff modal.
- [ ] Source AI is not selectable as its own target.
- [ ] One or more other saved AI slots can be selected.
- [ ] Presets `批判 / 検証 / 改善 / 要約` can all be selected without type/runtime error.
- [ ] Free text instruction can replace the preset text.
- [ ] Handoff sends source AI response as Reference, not Instruction.
- [ ] Handoff result is displayed separately from the original comparison result.
- [ ] Handoff result has no `他AIへ渡す` control; automatic second hop is impossible.
- [ ] Handoff result may be explicitly added to Context by the user.
- [ ] Adding Handoff result to Context does not trigger another AI request.

## I. UX regression — High
- [ ] Response copy button copies the full response and gives temporary feedback.
- [ ] Handoff response copy button works.
- [ ] Context panel filters: all / active / persistent / AI-generated work.
- [ ] Disabled Reference is visually distinguishable.
- [ ] Context provenance, scope, and lifetime badges are readable in light and dark mode.
- [ ] Context deletion confirmation stays centered in the Tauri window.
- [ ] TextPad deletion and paste-history confirmation stay centered.
- [ ] Column resize still works after Context/Handoff changes.
- [ ] Narrow window layout remains usable.

## J. Stable smoke scenario — Critical
Run this exact scenario end-to-end:
1. Start app with a clean session.
2. Enable both ChatGPT and Claude.
3. Set a Global Instruction: `結論と不確実性を分けてください。`
4. Set ChatGPT-specific Instruction: `構造上の論点を優先してください。`
5. Add a TextPad Reference and leave it enabled.
6. Ask the same question to both AIs.
7. Confirm both responses complete and Usage/Cost appears.
8. Add ChatGPT response to Context.
9. Ask a second question and confirm active Context is visible before send.
10. Open ChatGPT's first response → Handoff → Claude → `批判`.
11. Confirm Claude's Handoff answer appears in the one-hop section.
12. Confirm there is no automatic second-hop control on that result.
13. Save Claude's Handoff result to Context manually.
14. Mark one Reference persistent and another session-only.
15. Restart the app.
16. Confirm only persistent Context remains.
17. Confirm Usage totals remain.
18. Confirm no request was sent merely because Context was restored.

If all Critical items pass, tag the snapshot as `v0.7-stable` and only then begin the next architectural feature branch.
